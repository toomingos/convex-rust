# "use rust" actions: a wasm runtime for Rust actions in self-hosted Convex (experimental, opt-in per project)

> Draft status: this is the first commit of a two-commit stack. The second commit (opt-in native worker process,
> `PR-BODY.md`) is described separately and builds on this one. Numbers are for the patch generated from fork head
> `a5d46a5` against upstream `342530f`; regenerate with `release/make-patches.sh` if the fork has moved.

## What this adds

Convex actions written in Rust. A project keeps a crate in `convex/rust/`. The CLI builds it for
`wasm32-wasip1`, pushes the module with the rest of the functions, and the backend runs it in an embedded
`wasmtime` instance, one instance per invocation. Functions show up in the generated API as `api.rust.<module>.<fn>`
(typed from the Rust signature) and are called like any other action.

Rust functions are actions and HTTP actions only. Queries, mutations, components and the schema stay in TypeScript;
Rust calls them through `ctx.run_query` / `ctx.run_mutation` / `ctx.run_action`, plus scheduler, storage, auth,
`fetch` (streamed responses), env, logging, time and async tasks.

Nothing changes for projects without a `convex/rust` directory.

## How it works

- Guest ABI v1: a core wasm reactor module with a small set of `convex.*` imports and `convex_*` exports; all
  structured data is UTF-8 JSON in the Convex JSON export format. Contract: `contracts/ABI.md`, function manifest
  `contracts/MANIFEST.md`.
- Backend, `crates/isolate/src/environment/rust/`: the wasmtime host (`core.rs`), the bridge to the action
  environment (`backend.rs`, `dispatch.rs`, `mod.rs`), optional host-side `crypto/*` ops
  (`host_crypto.rs`, additive to ABI v1) and task spawning. Dispatch is a branch next to the V8 and Node action paths in
  `application_function_runner/mod.rs`.
- Push time, `crates/application/.../rust_analyze.rs`: the pushed module is parsed (never run for analysis) for
  its exports and manifest, and turned into the same analyzed-module structure TypeScript modules produce, so
  argument validation, visibility, the dashboard and function logs behave as for any action.
- CLI, `npm-packages/convex/src/cli/`: `convex rust init` scaffolding, toolchain checks and diagnostics, the wasm
  build and size warning, push as module source, `api.rust.*` codegen (`codegen_templates/rust_api.ts`), and
  `convex dev` / `deploy` integration.
- Limits: the same user timeout as TypeScript actions, 512 MiB of linear memory by default, the usual argument and
  result limits (`docs/rust/limits.md`). Timeout and memory errors use the existing messages where there is one.
- Safety: wasm is sandboxed by construction (no ambient files, sockets or threads). All I/O goes through host
  imports that use the existing action syscalls and limits.

### HTTP actions

`#[http_action]` functions are registered as internal actions (manifest `kind:"http"`) and routed by a generated
`convex/_generated/rustHttp` helper: `rustHttpAction("<module>:<fn>")` is a V8 `httpAction` that passes the request
(head, base64 body, buffered) to the internal action and builds the `Response` from the result. Buffered both ways:
request body under about 12 MiB, collected response up to 20 MiB. Streaming HTTP actions need the stock V8 host
(the `convex-rust` npm package path); this runtime does not.
